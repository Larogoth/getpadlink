For schools and IT

PadLink runs on the teacher's own PC. There's no PadLink server, no account with us, and no analytics or tracking.

Student privacy

  • Students don't create accounts. They join with the lesson's code and pick their name from the teacher's class list.
  • Student boards, raised hands and poll answers are kept only in the PC's memory during the lesson, and are deleted when the class closes.
  • Class lists hold names and, if the teacher chooses, a team and seat number. Nothing else.
  • Google Drive: PadLink only gets the files the teacher picks, and never changes or shares anything in their Drive.

School networks

  • On simple networks, the teacher's iPad and students' devices (Chromebooks, laptops or tablets, in any web browser) connect straight to the PC.
  • Where they can't, Remote mode connects them straight to the PC, peer to peer and encrypted end to end (WebRTC, as in video calls). PadLink's small signaling server only introduces the two sides; it can't read or join the connection, because each device checks the PC's own key from the pairing code. Where a network blocks direct connections, an encrypted relay is used (TURN, including over port 443), still unreadable in between. No account or sign-in is needed. Settings → Connecting on the PC shows which way each device connected right now (direct or through the relay).
  • PCs that used Remote mode before November 2026 keep Microsoft's Dev Tunnels relay until a teacher switches in Settings → Connecting. Dev Tunnels runs over port 443 and needs a sign-in with a GitHub or Microsoft account.

Addresses to allow in web filters

Students' devices and the teacher's iPad

  • padlink-signal.getpadlink.workers.dev, stun.cloudflare.com and turn.cloudflare.com (UDP 3478, TCP 443): Remote mode
  • padlink-app.github.io: students' join page when they join through Remote mode
  • *.devtunnels.ms: Remote mode on PCs still set to Dev Tunnels
  • padlink-app.github.io: PadLink Go

The teacher's PC, for Remote mode (outgoing connections only, port 443)

  • *.devtunnels.ms and *.rel.tunnels.api.visualstudio.com (including global.rel.tunnels.api.visualstudio.com): Microsoft Dev Tunnels
  • aka.ms and tunnelsassetsprod.blob.core.windows.net: downloading Microsoft's Dev Tunnels tool, the first time
  • github.com, login.microsoftonline.com and microsoft.com: signing in

The teacher's PC, for updates

  • github.com and release-assets.githubusercontent.com: checking for and downloading updates

Google Drive (only if the teacher uses it)

  • larogoth.github.io: PadLink's page for Google's file picker
  • Google's own addresses: accounts.google.com, apis.google.com, docs.google.com and www.googleapis.com. In Google Workspace, IT may also need to allow PadLink in the Admin console.

Microsoft keeps its own list for Dev Tunnels in Dev tunnels security.

Updates

PadLink checks for updates by itself, and every update is checked against PadLink's own signature before it installs.
